(ADR-0004 item 2) can be written without choices; it reuses the shared xorshift primitives of `sting.md` 6.2.

## 1. What it does (5 lines max)

The T-1 spreads `pulses` hits as evenly as possible over `steps` (Björklund), rotates the result, and plays each hit
with a pitch taken from a phrase contour (sine, triangle, saw, arch ...) plus an optional ratchet (1 to 16 repeats with
an accelerating or decelerating "bouncing ball" spacing), snapped to a scale [V, 03 to 05]. Accent, probability, random
modulation and per-step parameter locks sit on top [V, 06]. As the **EUCLID** algorithm it keeps even-spacing hit
placement (the one thing none of the other five families has), a 16-step maximum loop with LEN as polymeter, a
seeded contour melody, and ratchets, with 4 dice layers, 4 knob morphs, all deterministic from four seeds.

## 3. Layers (what can be diced independently)

Four layers, each with its own 16-bit seed. In the source nothing is diced (the only random source is the shared
per-track LFSR whose stream shifts whenever any draw is added or removed, F19); this design gives each layer its own
seed so one can be re-rolled alone. Layer names are the on-screen dice labels (max 6 characters).

| Layer (screen label) | What dicing it changes | What stays fixed |
| --- | --- | --- |
| ROT (`ROT`) | The rotation of the Euclidean pattern, `R = r16 mod LEN` (seed 0 = no rotation). So the same evenly spaced hits start on a different step: a new groove from the same hit count. | HITS, LEN, which melody note each hit plays (ordinal), accents, ratchets, scale |
| NOTES (`NOTES`) | The contour shape (one of 6) and the per-hit jitter. So the melody changes. | Which steps play, accents, ratchets, all four knob values, scale, root |
| ACCENT (`ACCNT`) | The seeded priority order in which hits become accented as the ACCNT knob rises. | Rhythm, pitches, ratchets |
| RATCH (`RATCH`) | Which hits ratchet (2 or 3 repeats) and with which pace direction (accelerating, even, decelerating). Fixed odds, no knob. | Rhythm, pitches, accents |

Layers are keyed by hit **ordinal** `h` (the h-th hit in step order), not by step position, so a ROT dice or a LEN
change moves the whole figure without re-assigning notes, accents or ratchets to different hits [D]. A **dice all**
action re-rolls the four seeds in one gesture and **undo dice** recalls each layer's previous seed (two bytes per
layer), as in `sting.md` section 3; the physical buttons are the control map's job.

## 4. Morph candidates (continuous knob transforms)

Every morph is a pure function of (seeds, knob values); turning a knob back restores the previous pattern exactly.
Cost figures are for recomputing the 16-step cache after a knob detent (main loop, not the ISR).

| Morph | Range | Musical effect | Cost per step (rough) |
| --- | --- | --- | --- |
| HITS (pulses `p`) | 1..16, default 5 (effective `min(p, LEN)`) | Björklund `E(p, LEN)`: 1 = one hit, 4 of 16 = four on the floor, 5 of 16 = `x..x..x..x..x...`, 16 = every step. Every value is evenly spaced, so a sweep always sounds like a groove (unlike rank-order density, which thins at random). | One Björklund call (about 100 integer ops at LEN <= 16) + one rotate |
| LEN (steps `n`) | 2..16, default 16 | Loop length; the pattern is re-spread over `n` steps. 12 or 7 against other 16-step channels gives polymeter (`E(5,12)` = `x..x.x..x.x.`). | Same call |
| SPAN (contour excursion, semitones) | 0..24, default 12 | Height of the contour above the root: 0 = every hit hammers the root, 24 = two octaves of melodic motion. | One `eval_phrase` + one quantise per hit |
| ACCNT (accent count `a`) | 0..8, default 2 | The first `a` hit ordinals in the ACCENT-seed order get velocity 120, the rest 80. 0 = flat. | 1 table read + compare per hit |

Rejected as morphs (kept out of the four knobs): rotation (it is the ROT dice layer; swapping K2 to a ROTATE knob is a
table edit, see 6.6), ratchet amount (RATCH is a dice layer with fixed odds, "dice until none"), gate length (global
GATE), pace amount (sign comes from RATCH, magnitude fixed), probability (see 6).

## 6. Redesign for this sequencer

- **Proposed name on screen (max 6 characters):** `EUCLID`
- **Morphs (on-screen labels, max 6 characters each):** K1 `HITS`, K2 `LEN`, K3 `SPAN`, K4 `ACCNT` (ROW 1); S1 `OFFSET`, S2 `RATCH`, S3 `PUNCH`, S4 `CURVE` (ROW 2). Full list: docs/design/FULL_CONTROL.md 3.2. (The control map owns which context these knob roles apply in.)
- **Dice buttons (which layers):** four layer targets `ROT`, `NOTES`, `ACCNT`, `RATCH`, plus dice-all and undo-dice.
  Physical button binding is a control-map table row; this spec only declares the targets.
- **What we drop from the original, and why** (all dropped parameters are `CycleParams` fields unless stated):
  - 6 tracks x 6 cycles and cycle switching: a channel is one lane (rule 3); scenes/cycles are the song/scene spec's
    job. Cycle switching is called "the T-1's central performance gesture" in F7; here the performance gestures are
    knobs and dice, and F7 disappears with the cycle cache.
  - `steps` 17..64 and the 64-bit masks: keys reach 16 steps and a 16-bit mask keeps the cache small (owner question
    26 if 32 or 64 is wanted).
  - `division`, per-pattern `swing`, `groove_id`, `delay_ticks`, `sustain`, `time`: global DIV/SWING/GATE
    (owner decision 4); `groove_id` and the others were never read or never reachable (F11).
  - `probability`, `random_depth/rate/targets`, the LFSR modulation, CC lane (`cc_target/value`): free-running state
    breaks "same settings and seed play the same pattern" (rule 4) and the draws are correlated (F16, F19). The seeded
    per-hit jitter and the ratchet layer replace them. A CC lane is owner question 6.
  - `style` (arp direction), `voicing`, `chord_size`: monophonic bass use; style is also wrong in code (F5). Chords and
    note order belong to ARP (deferred), which would start from these functions (6.8).
  - `scale_id`, `root_note`, `pitch_offset`, `master_scale/master_root`: replaced by the single global scale control
    (owner decision 3); the "master link" that no control could set (F11) is just the normal case now.
  - P-locks (11 entries, 3 params, no UI, F12/F17): replaced by pins from the white keys (6.5).
  - `active_mask_lo/hi` Step Mod and its UI (F8, F11): replaced by pins (same effect, plus a pitch).
  - TEMP snapshot, GLOBAL mode, the flash bank layout (F6, F12, F15): out of scope; persistence is the project/state
    spec's job (flash was skipped by owner decision 1).
- **What we improve over the original:**
  - Every random decision is seeded per layer, so a layer can be re-rolled alone, undone and saved (rule 4).
  - The two broken contours (ARCH, INV A, F3) are fixed and RAND is replaced by seeded jitter, so six real shapes.
  - The melody follows the hit ordinal, so rotating or re-spreading the rhythm never changes which note comes when.
  - Accent is a monotonic count (ACCNT) instead of a fixed 30% LFSR chance or "step 0 only".
  - Muting a channel keeps its phase (F10): the step index is derived from the clock (`t mod LEN`), not from a
    counter that stops while muted.
  - Pitch is root-anchored on a bass base note (36) with a SPAN morph; the device default bass peaked at +84 semitones
    until F4 was fixed (10.3 question 1).
- **Parameters that must not exist (settings creep that breaks rule 1):** rotate as a menu value, probability,
  random depth/rate/targets, chord size, voicing, arp style, per-channel scale or root, per-channel division or
  swing, repeats/pace/offset/time/sustain sliders, groove id, p-lock pages, cycle select.

> P1-013: parameters listed above under "must not exist" or "drop" that are now ROW 2 morphs (offset, direction, slide amount, accent depth, ratchet amount, contour curve, gate-lane length, stage divider cap, velocity depth) are no longer forbidden; everything else listed stays cut. See FULL_CONTROL.md 3.1 to 3.4.

### 6.1 Parameters (data table; ranges and defaults)

This table is the single source for the on-screen labels, ranges and defaults. A remap is an edit to this table.

| Id | Kind | Label | Range | Default | Stored as |
| --- | --- | --- | --- | --- | --- |
| `hit` | morph, K1 | `HITS` | 0..16 | 5 | u8 |
| `len` | morph, K2 | `LEN` | 2..16 | 16 | u8 |
| `spn` | morph, K3 | `SPAN` | 0..24 | 12 | u8 |
| `acc` | morph, K4 | `ACCNT` | 0..8 | 2 | u8 |
| `off` | morph, S1 | `OFFSET` | 0..15 | 0 | u8 |
| `rat` | morph, S2 | `RATCH` | 0..8 | 4 | u8 |
| `pun` | morph, S3 | `PUNCH` | 0..47 | 40 | u8 |
| `crv` | morph, S4 | `CURVE` | 0..6 (AUTO SINE TRI SAW+ SAW- ARCH INV) | 0 | u8 |
| `s_rot` | dice seed | `ROT` | 0..65535 | 0 (no rotation) | u16 |
| `s_notes` | dice seed | `NOTES` | 0..65535 | `(0x3A5D * (ch*4 + 1)) & 0xFFFF` | u16 |
| `s_acc` | dice seed | `ACCNT` | 0..65535 | `(0x3A5D * (ch*4 + 2)) & 0xFFFF` | u16 |
| `s_rat` | dice seed | `RATCH` | 0..65535 | `(0x3A5D * (ch*4 + 3)) & 0xFFFF` | u16 |
| `p_*` (x4) | previous seed for undo-dice | n/a | 0..65535 | equal to the seed (nothing to undo) | u16 each |
| `pin_mask`, `pin_note[16]` | step-entry overrides (6.5) | n/a | mask 0..65535; offset 0..96 | 0, 0 | u16 + 16 x u8 |

`ch` is the 0-based channel index. When the user dices a layer the new seed is the low 16 bits of the audio sample
counter at the press (forced to 1 if that is 0 for ROT), the only non-deterministic moment; it is stored, so playback
afterwards is fully deterministic. The global settings read by this algorithm are scale, root, DIV, SWING and GATE
(owner decision 4); EUCLID owns none of them.

### 6.2 Random primitives (normative, needed for golden files)

Identical to `sting.md` 6.2 (xorshift32 `next()`, `rnd(n) = (next() >> 8) % n`, Fisher-Yates `shuffle`, and
`init(seed16, salt)` = `x = ((seed16 << 16) | seed16) ^ salt; if x == 0: x = 1; draw 4 and discard`). Each layer
builds its own state from its own seed and uses no other layer's stream. Salts, new for this algorithm **[D]**:
ROT `0x1E3779B9`, NOTES `0x2545F491`, ACCENT `0x1B873593`, RATCH `0x3C6EF372`. This **replaces** the LFSR
(`t1_lfsr_next/_modulate/_byte`, F16, F19) completely; shared with ACID, SNAKE, STAGE, so one implementation.

### 6.3 Procedure (step by step; every layer is computed from its seed only, then morphs are applied)

Let `n = LEN`, `p = min(HITS, n)`. Global: `root` (0..11), `scale` (id into the shared mask table), `DIV`, `SWING`,
`GATE`.

**Hit mask.**
1. `m0 = t1_euclidean_bjorklund(n, p)` (reused unchanged).
2. **ROT layer** (stream `init(s_rot, SALT_ROT)`): `r16 = rnd(65536)` if `s_rot != 0`, else 0. `R = r16 mod n`.
   (One draw, so `R` is a pure function of `(s_rot, n)` and returns when LEN returns.)
3. `m1 = t1_euclidean_rotate(m0, n, R)` (reused unchanged; positive R moves each hit R steps lower, wrapping).
4. Pins: `hitmask = m1 | pin_mask` limited to the lowest `n` bits. A pin never removes a hit.
5. `H` = popcount of `m0` (generated hits only). The **ordinal** of a hit at rotated step `i` is its rank in the
   *unrotated* pattern: `j = (i + R) mod n` (the step it came from, because rotation moves bit `k` to `k - R`), and
   `h = popcount(m0 & ((1 << j) - 1))`. So ROT moves the whole figure, notes and all, as one block [D]. **Pinned
   steps that are not generated hits do not consume an ordinal** (owner question 24; same as `rhythmic-steps.md`).
   The rebuild stores `h` per step in the cache, so the ISR does no popcount.

**NOTES layer** (stream `init(s_notes, SALT_NOTES)`):
1. `shape = 1 + rnd(6)` (1 SINE, 2 TRI, 3 SAW U, 4 SAW D, 5 ARCH, 6 INV A; FLAT 0 and RAND 7 are not used).
2. `jit[h] = rnd(5) - 2` for `h = 0..15` (always 16 draws, so the stream is the same whatever `H` is).

**SPAN and pitch** (pure, per ordinal `h`):
1. `c = t1_harmony_eval_phrase(shape, SPAN, h, H)` (reused; **requires the F3 fix**; returns 0 if `SPAN = 0` or `H <= 1`).
2. `j = (SPAN > 0) ? jit[h] : 0`.
3. `raw = 36 + root + max(0, c + j)` [D]: the line never goes below the root; the negative half of SINE and the
   dip of INV A become root hammering.
4. `note[h] = t1_harmony_quantize(raw, root, scale)` (reused; snaps at or below the nearest scale tone, owner
   question 16; chromatic returns `raw`). Pitch ceiling is `36 + 11 + 24 + 2 = 73`.
   Pinned step note = `clamp(36 + root + pin_note[i], 0, 127)`, then the same quantise **is not applied** (the player
   typed it).

**ACCENT layer** (stream `init(s_acc, SALT_ACCENT)`): `ord = [0..15]; shuffle(ord, 16)`; walking `ord` from the front,
the first `ACCNT` entries that are `< H` select accented ordinals. Velocity 120 if accented, else 80 (the
velocities of `sting.md`); a pinned step is always 80.

**RATCH layer** (stream `init(s_rat, SALT_RATCH)`): for `h = 0..15`, always two draws: `u = rnd(100)`,
`d = rnd(3)`. `reps[h] = 2` if `u < 15`, `3` if `u < 20`, else `1`. `pace[h] = (d - 1) * 32`
(-32 accelerating, 0 even, +32 decelerating). Pinned steps have `reps = 1`.

**Playback** (ISR, per step; step index `i = t mod LEN`, `t` from the clock, so mute keeps phase):
1. Step start tick = the global grid with global SWING; `Ls` = that step's swung length in ticks.
2. If `hitmask` bit `i` is clear, rest. Otherwise the note, velocity, `reps`, `pace` come from the cache entry.
3. Ratchet timing: call `t1_pace_eval_ratchet` with `repeats = reps`, `pace`, `offset = -20`, `time = GATE` mapped to
   1..127 (7.5), `velocity = vel`, and the length `Ls`. Repeat `k` starts at `tick_offsets[k]`, lasts `gate_ticks[k]`, with
   velocity `velocities[k]`. With `reps = 1` this is one note at offset 0 and gate `Ls * time / 128`.
4. All note-ons and their note-offs for the step are queued **together** at the step start (F9 cannot occur: at most
   3 note-on/off pairs per step per channel; the 256-entry queue holds 128 such steps).
5. A sounding note is never left without a scheduled off: stop, panic, algorithm or MIDI-channel change send
   note-off for each sounding note and CC123 on that channel.

**Worked example** (root C = 0, scale P-MIN id 10 `{0,3,5,7,10}`, HITS 5, LEN 16, SPAN 12, `s_rot = 0`, shape SINE,
all `jit = 0`, ACCNT 0): `E(5,16)` = `x..x..x..x..x...`, hits at steps 0, 3, 6, 9, 12; `H = 5`. `eval_phrase(SINE, 12, h, 5)` =
`0, 11, 7, -7, -11` (phase = `h*360/5`). `raw = 36 + max(0, c)` = `36, 47, 43, 36, 36`; quantise at or below: 47 (pitch class 11)
-> 46, 43 (class 7) stays. Notes `36, 46, 43, 36, 36` at velocity 80, one note per hit, no ratchets (`reps` all 1).
Dicing ROT to `R = 2` moves the hits to steps 14, 1, 4, 7, 10 and the notes with them: step 14 plays 36 (old step 0), step 1 plays 46, step 4 plays 43, step 7 plays 36, step 10 plays 36.

### 6.3a Dice and knob latency (VISION rule 1: changes feel immediate)

- The algorithm is **stateless between steps**: no slide pairing, no held note across steps. A step reads only its
  own cache entry. So no next-step commit is needed (contrast `sting.md` 6.3a).
- The main loop rebuilds the cache after each knob detent or dice press: one Björklund (<= 16 steps), one rotate,
  about 16 `eval_phrase` + quantise calls, about 100 xorshift draws, in all roughly 1,500 integer ops (tens of
  microseconds). It writes into the **inactive** one of two cache copies and then flips one `volatile uint8_t`
  index; the ISR reads that index once at the start of each step. A change is therefore audible at the **next step**
  boundary (up to one step, 125 ms at 120 BPM and 1/16) plus at most one main-loop frame (16 ms). A step in progress
  is never altered, so no hung note is possible.
- Knob turns are unthrottled: the rebuild is cheaper than a frame.

### 6.3b ROW 2 morphs (P1-013, normative; all defaults are neutral, so the procedure above is unchanged at defaults)

All four are applied in `build()`; none needs a change in `step()`.
- **OFFSET `off` 0..15 (default 0).** Hit mask step 2 becomes `R = ((r16 mod n) + off) mod n`, with `r16 = 0` when
  `s_rot == 0`. The dice ROT and the knob add; the note ordinal rule of step 5 uses this total `R`.
- **RATCH `rat` 0..8 (default 4).** RATCH layer: `P2 = 15 * rat / 4`, `P3 = 20 * rat / 4` (integer division);
  `reps[h] = 2` if `u < P2`, else `3` if `u < P3`, else `1`. `rat = 4` gives the original 15 % / 5 %; `rat = 0` gives
  no ratchets; `rat = 8` gives 30 % / 10 %. The two draws per hit are unchanged. `pace[h]` is unchanged.
- **PUNCH `pun` 0..47 (default 40).** ACCENT layer: accented velocity `min(127, 80 + pun)`, unaccented and pinned 80.
- **CURVE `crv` 0..6 (default 0).** NOTES layer step 1: always draw `d = 1 + rnd(6)`, then `shape = crv` if `crv > 0`
  else `d` (1 SINE, 2 TRI, 3 SAW U, 4 SAW D, 5 ARCH, 6 INV A). The jitter draws follow as before, so they are the same
  for every `crv`.

### 6.4 Channel RAM and CPU

| Item | Bytes |
| --- | --- |
| 8 morph values (ROW 1 and ROW 2) | 8 |
| 4 seeds + 4 previous seeds | 16 |
| Pin mask + 16 pin notes | 18 |
| Layer scratch (shape 1, jit 16, ACCENT order 16) | 33 |
| Playback cache x2 (hit mask 2, note 16, accent mask 2, reps 2 bits x 16 = 4, pace 2 bits x 16 = 4) | 56 |
| ISR playback state (sounding note 1, spare 1) | 2 |
| **Total** | **133 B per channel** (well under 2 KB; scratch can be regenerated from the seeds) |

CPU: a full recompute is the roughly 1,500 integer ops above, on the main loop; the ISR per step does one index read,
one bit test, and for a firing step one `t1_pace_eval_ratchet` (up to 3 iterations of Q15 arithmetic, about 100 ops).
The T-1's own per-pulse work (the 192-PPQN loop over 6 tracks, LFSR draws, chord building) is not used.

### 6.5 Step entry interplay (rule 3: steps on the 16 white keys OR the algorithm)

- A step typed on the white keys while EUCLID is selected writes a **pin** at step position `i = 0..15`:
  `pin_mask |= 1<<i`, `pin_note[i] = clamp(key note - 36 - root, 0, 96)`. The step fires with that note at velocity 80,
  whatever HITS says, and has no ratchet.
- Pins are keyed by step position, so they survive every dice and every knob. A pin at `i >= LEN` is stored but silent
  until LEN is raised (owner question 18). Clearing a pin returns the step to the generated line.
- This replaces the T-1's p-locks and Step Mod, whose device UI was missing (F8, F11, F12). The key-entry gesture
  itself belongs to the channel/step-entry spec and must cite this section.

### 6.6 Flex points (ADR-0004 addendum): what is a table edit, what is not

- ROW 2 (P1-013): which knob slot drives OFFSET, RATCH, PUNCH, CURVE (`knob_morph[8]`), their ranges and defaults, the ratchet base odds 15 and 20, the accent velocity base 80.
Remappable by editing a table row, no algorithm code change:
- Which knob drives which morph (K1..K4 <-> HITS/LEN/SPAN/ACCNT), labels, ranges, defaults. For example K2 `LEN` -> a
  `ROTATE` knob (`R = knob` instead of `r16 mod n`) is a table change plus a one-line mapping.
- Which physical button dices which layer; gestures for dice-all and undo-dice.
- Constants: base note 36, velocities 120/80, ratchet odds 15/5 %, pace magnitude 32, velocity slope -20, shape list
  (the 6 shapes), jitter range +-2, SPAN default, the default seed multiplier 0x3A5D, `time` mapping of GATE.
- Splitting NOTES into shape and jitter (two seeds), or adding a layer that reuses an existing stream.

Not changeable without algorithm code: the xorshift generator, salts and shuffle (they define the golden files); the
ordinal-keyed layers; the Björklund and rotate functions; hit-mask length (16 bits); the stateless per-step cache model.

## 7. Risks and open questions

Mostly [V]: unlike the other families this one is built from code that runs, with host probes. Design points that rely
on something **not** verified (⚠ or unmeasured):

1. **⚠ Timing on the FM-1.** The ratchet timing relies on 192-PPQN ticks derived from audio blocks (about 0.7 ms
   granularity, F13) and on the "ISR < 80 us" figure, which is a host or design number, **not measured on the
   device** [07 ⚠]. With 3 repeats in a 1/16 step at 300 BPM the spacing is about 17 ms, well above the granularity, but
   it is not measured. The design does **not** depend on the 80 us figure (the ISR work is far smaller than the T-1's).
2. **⚠ Stack headroom for Björklund.** `t1_euclidean_bjorklund` has a 64-entry local array (about 1 KB with padding).
   It runs on the T-1's ISR path today; this design moves it to the main loop. The main-loop stack size was not read in
   this task; the executor must check it (FM1_GUARD_STACK is enabled in main.c) or cap the array at 16 entries.
3. **F3 must be fixed first.** SPAN with ARCH or INV A is wrong until `t1_harmony_eval_phrase` is repaired. The shapes
   SINE, TRI, SAW U, SAW D are sound [V].
4. **F2 residue.** The scale name table is stale; if the single global scale control (owner decision 3) shows names
   from `T1_SCALE_NAMES` it will mislabel scales. Use the UI's names (CHROM..DIM) and delete the stale table.
5. **⚠ GATE mapping.** `time` = global GATE needs a definition of the global GATE range (the control-map spec's job).
   Assumed: GATE is a percent of the step, mapped `time = clamp(GATE_pct * 127 / 100, 1, 127)`; at the T-1's default
   `time` 64 the gate is 50% of a ratchet interval. Not confirmed.
6. **⚠ TB-3 behaviour with fast repeats.** Whether the TB-3 retriggers cleanly with 3 repeats of 1/16 / 3 at short gates
   (about 5 ms at 300 BPM) is untested on hardware (OWNER_QUESTIONS 8 is the same class of check).
7. **Snap direction.** `t1_harmony_quantize` snaps **down** only (owner question 16). On sparse scales (P-MIN) low SPAN
   values flatten to repeated notes; a "nearest" snap would sound different.
8. **Pitch is a contour, not a riff.** EUCLID scores 2 for bassline use (section 5). If the owner wants an acid line
   from it, the melody should come from owner question 22/25 (a contour walk), not from more shapes.
9. **Ratchet without a knob.** RATCH amount is fixed (about 20% of hits ratchet); an owner who wants a ratchet knob
   must give up one of HITS/LEN/SPAN/ACCNT, or use a shifted gesture (same trade as OWNER_QUESTIONS 7).
10. **Cycles retired.** The T-1's six cycles per track are not carried over; if scenes are wanted they belong to the
    song/scene spec and EUCLID's state (129 B) is small enough to store several.
11. **Engine dependency.** The queue-based note scheduling (retained from `torso_t1.c`) vs a per-channel scheduler is the
    channel-engine spec's decision; ADR-0003, which ADR-0004 cites for the uniform algorithm interface, is not in
    `docs/project/decisions/` at the time of writing.

## 8. Recommendation

**INCLUDE in v1.** EUCLID is the one algorithm in the catalogue that places hits by even spacing, which is the thing
none of the other five assessments provides (RHYTHM explicitly lacks it) and which musicians expect from a
rhythm-first sequencer: every HITS and LEN position is a groove, so the knobs are safe to perform on stage. The code
is already in the firmware and verified (`t1_euclidean_bjorklund`, `_rotate`, `t1_harmony_quantize`, the ratchet maths),
so the cost is small: about 129 bytes per channel and no ISR load beyond one cache read. Björklund, rotate and quantise
are reused unchanged, the ratchet maths needs only a scalar signature, and only the contour (F3) needs a bug fix before use. It is the fastest route to a
playing, performable TB-3 line with no settings. Its weakness is pitch: a contour is an arpeggio, not an acid riff, so
it should sit beside ACID, not replace it; dicing NOTES gives a different shape, not a different riff. We therefore
recommend a **separate EUCLID algorithm** (rather than only offering Euclid placement to other algorithms) because
the placement, ordinal-keyed layers and contour pitch lane work together, with RHYTHM staying deferred (its groove-template
order remains a possible second density source) and ARP deferred (it would inherit the chord and voicing functions retired
here). If P1-010 limits v1 to three algorithms, drop EUCLID last: ACID, SNAKE and STAGE share the random-order
placement, so EUCLID is the least redundant of the four.
